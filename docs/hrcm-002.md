# 《医院全科随访系统》产品功能规格文档

## 1. 医院管理端（Web）

### 1.1 系统管理

#### 1.1.1 新建用户

**功能描述**：通过填写基础信息与权限信息创建新的系统用户账号，用于医院管理端的人员账号管理与权限分配。

**触发方式**：用户点击“新建用户”按钮。

**前置条件**：

1. 用户已登录医院管理端；
2. 用户拥有“系统管理-用户管理-新增”权限；
3. 当前医院用户总数未达到系统上限；
4. 系统角色已预先配置完成（至少存在1个角色）。

**输入**：

- **必填数据**：
  - 用户姓名（文本，1-50字符）
  - 登录账号（文本，4-30字符，字母/数字/下划线）
  - 手机号（11位数字，合规校验）
  - 所属角色（单选下拉框，源于角色列表）
  - 所属科室（单选下拉框，源于科室字典）
  - 账号状态（单选：启用/禁用，默认“启用”）
- **可选数据**：
  - 邮箱地址（合规校验）
  - 工号（0-30字符）
  - 用户备注（0-200字符）
- **自动获取**：
  - 用户ID（UUID）
  - 初始密码（123456）
  - 创建人信息、创建时间

**输出（成功时）**：

1. 弹出 Toast 提示：“用户创建成功！”
2. 页面自动跳转至用户详情页；
3. 系统自动向用户发送账号通知（如开启）；
4. 账号状态为“启用”时，用户可立即登录。

**输出（失败时）**：

1. 登录账号已存在：提示“该登录账号已存在，请更换”；
2. 手机号已绑定：提示“该手机号已被使用”；
3. 手机号格式错误：提示“请输入正确的手机号格式”；
4. 必填项缺失：提示“该字段为必填项”；
5. 角色失效：Toast 提示“所选角色不可用，请刷新重试”；
6. 达到上限：Toast 提示“当前医院用户数量已达上限”；
7. 系统异常：Toast 提示“创建失败，请稍后重试”。

**边界条件**：

- 用户数量上限：1000人（可配置）；
- 账号唯一性：医院内唯一；
- 手机号唯一性：全系统唯一；
- 连续操作响应 ≤ 3秒；
- 禁用账号不可登录。

#### 1.1.2 用户列表

**功能描述**：展示当前医院下所有用户信息，支持筛选、分页、批量操作。

**触发方式**：

1. 点击菜单“系统管理-用户管理”；
2. 用户操作（新建/编辑/删除）后的自动回退。

**前置条件**：

1. 用户已登录并拥有“查看”权限；
2. 存在至少一条用户数据。

**输入**：

- **可选筛选条件**：
  - 用户姓名、登录账号、手机号（模糊/精确匹配）
  - 所属角色、所属科室、账号状态
  - 创建时间范围
- **分页参数**：
  - 页码（默认1）、每页条数（10/20/50/100）

**展示字段**：

1. 用户姓名、登录账号、手机号
2. 所属角色、所属科室、账号状态
3. 创建时间
4. 操作：查看、编辑、重置密码、启用/禁用、删除

**输出（成功时）**：

1. 正常展示分页数据及总记录数；
2. 支持排序（默认创建时间倒序）；
3. 支持批量操作勾选。

**边界条件**：

- 单页上限：100条；
- 查询响应 ≤ 3秒；
- 批量操作上限：50条；
- 不可删除当前登录用户及系统超管。

#### 1.1.3 编辑用户

**功能描述**：修改已有系统用户信息及权限。

**触发方式**：点击“编辑”按钮。

**前置条件**：拥用“编辑”权限，且用户账号存在。

**输入**：

- **必填数据**：姓名、手机号、所属角色、所属科室、账号状态
- **可选数据**：邮箱、工号、备注
- **只读字段**：登录账号、用户ID、创建时间等

**输出（成功时）**：

1. Toast 提示：“用户信息更新成功！”
2. 页面返回列表，数据实时刷新；
3. 修改角色或禁用状态后立即生效。

**边界条件**：

- 不可编辑更高级别权限的账号；
- 不可修改自己的角色（防锁死）；
- 禁用生效时间 ≤ 1分钟。

#### 1.1.4 删除用户

**功能描述**：清理无效账号。删除后不可登录，不再显示在常规列表。

**触发方式**：点击周期或批量“删除”按钮。

**页面行为**：弹出二次确认框。

> 确认删除该用户？删除后该账号将无法登录系统，此操作不可恢复。

**输出（成功时）**：

1. Toast 提示：“删除成功！”；
2. 若逻辑删除，标记 `is_deleted = true`。

**边界条件**：

- 批量处理上限：50条；
- 操作响应 ≤ 3秒；
- 审计日志记录变更前快照。

### 1.2 医生管理

#### 1.2.1 新建医生档案

**功能描述**：录入医生基础及执业信息，关联科室与系统账号。

**触发方式**：点击“新增医生”按钮。

**前置条件**：拥有“人员管理-新增”权限，字典（科室、职称、角色）已配置。

**输入**：

- **必填数据**：姓名、手机号（登录名）、所属科室、职称、角色权限
- **可选数据**：工号、简介、擅长领域、头像（<2MB, jpg/png）
- **自动获取**：医生ID、创建时间、创建人

**输出（成功时）**：

1. Toast 提示：“医生档案创建成功”；
2. 跳转至详情或列表页。

**边界条件**：

- 医生数量上限：默认2000人；
- 手机号全系统唯一；
- 图片上传异常处理及格式校验。

#### 1.2.2 编辑医生档案

**功能描述**：维护医生实时执业信息及权限。

**触发方式**：点击“编辑”。

**输入**：

- 可修改项包含必填基础信息、工号、简介、头像等。
- 只读项包括医生ID、创建时间。

**输出（成功时）**：

1. 提示更新成功；
2. 权限及状态变更实时生效。

**边界条件**：

- 审计日志记录所有变更字段。

#### 1.2.3 删除医生档案

**功能描述**：执行离职或错误数据的清理。

**触发方式**：触发“删除”按钮。

**行为**：二次确认确认后删除。

> 确认删除该医生？删除后该账号将无法登录系统，此操作不可恢复。

**边界条件**：

- 默认逻辑删除。
- 账号强制过期时间 ≤ 1分钟。

#### 1.2.4 医生批量导入

**功能描述**：通过 Excel 模板快速录入多名医生。

**触发方式**：点击“批量导入”。

**输入**：

- 上传文件（.xlsx, ≤ 5MB）

**处理逻辑**：

1. 校验文件格式及必填项；
2. 全局唯一性检查（手机号）；
3. 字典匹配性检查（科室、职称、权限）。

**输出**：

- 显示成功/失败条数；
- 提供失败明细 Excel 下载。

**边界条件**：

- 单次上限：5000条；
- 处理响应：5000条 ≤ 60秒。

### 1.3 科室管理

#### 1.3.1 科室列表

**功能描述**：管理科室组织架构及状态。

**触发方式**：点击菜单“组织架构-科室管理”。

**展示字段**：科室名称、编码、上级科室、负责人、电话、状态、创建时间。

**边界条件**：

- 默认按创建时间倒序；
- 查询响应 ≤ 3秒。

#### 1.3.2 新增科室

**功能描述**：建立组织层级。

**输入**：

- **必填数据**：名称（院内唯一）、编码（唯一）、上级科室（可空）、状态

**边界条件**：

- 最大层级：5级；
- 科室总数上限：500个。

#### 1.3.3 编辑科室

**功能描述**：调整名称、关联关系及详情。

**约束**：不可将上级设置为自身或其子级（循环校验）。

#### 1.3.4 删除科室

**规则要求**：

1. 存在医生或子科室时禁止删除；
2. 保留科室不得删除。

#### 1.3.5 科室状态切换

**影响**：禁用后不可分配新医生，但不影响历史归属。

### 1.4 组织架构可视化（树形管理）

**功能描述**：以树状视图直观展示医院、科室、医生关系。

**主要功能**：

1. 展开/折叠节点；
2. 拖拽调整科室归属；
3. 右键快捷菜单执行基础管理。

**管理规则**：

- 节点权限自动继承；
- 拖拽仅限于合法的层级逻辑（禁止跨机构或循环）。

## 2. 患者管理

### 2.1 患者分组

#### 2.1.1 创建分组

**功能描述**：建立静态（手动选择）或动态（条件筛选）患者群。

**分组类型**：

- **静态分组**：手动维护成员。
- **动态分组**：根据病种、手术、年龄、性别等条件自动聚合。

**输出**：

- 动态分组自动刷新计算结果。

**边界条件**：

- 分组上限：5000个。
- 筛选条件组合 ≤ 10个。

#### 2.1.2 管理分组（编辑/删除/查看）

**删除限制**：被随访计划引用的分组禁止删除。

**查看列表**：

- 展示脱敏后的患者基本信息（如：张\*三、138\*\*\*\*1234）。

### 2.2 患者档案

#### 2.2.1 新建患者档案

**功能描述**：建立患者的核心诊疗档案。

**输入**：

- **必填数据**：姓名、身份证号（唯一）、性别（自动识别）、生日（自动识别）、手机号、主诊断。
- **可选数据**：住院号、手术信息、主管医生、自定义扩展字段。

**输出**：

- 若开启自动随访，根据手术时间自动生成随访任务。

**边界条件**：

- 年龄自动精准计算。
- 单个档案扩展字段 ≤ 50个。

#### 2.2.2 档案维护与查看

**编辑限制**：身份证号、性别、出生日期建档后不可修改。

**详情展示**：

- 分 Tab 展示：基本信息、诊疗信息、扩展信息、随访记录、操作日志。

#### 2.2.3 扩展字段配置

**功能描述**：管理员自定义患者档案的扩展字段，控制字段在医生端和患者端的可见性与可编辑性。

**可配置项**：

- 字段名、类型（文本/数字/日期/单选等）、是否必填。
- 医生端/患者端及其可见性、编辑性。

#### 2.2.4 患者档案导入

**功能描述**：批量初始化或同步患者数据。

**规则**：

- 单次量 ≤ 5000条。
- 身份证号重复冲突处理：跳过/覆盖。
- 并发控制：同一用户不可并发多个导入任务。
