# 《医院全科随访系统》产品功能规格文档

## 1. 医院管理端（Web）

### 1.1 系统管理

#### 1.1.1 新建用户

**功能描述**：通过填写基础信息与权限信息创建新的系统用户账号，用于医院管理端的人员账号管理与权限分配。

**API 路径**：`POST /api/v1/users`

**触发方式**：用户点击“新建用户”按钮。

**前置条件**：
... (unchanged)
**边界条件**：

- 用户数量上限：1000人（可配置）；
- 账号唯一性：医院内唯一；
- 手机号唯一性：全系统唯一；
- 连续操作响应 ≤ 3秒；
- 禁用账号不可登录。

#### 1.1.2 用户列表

**功能描述**：展示当前医院下所有用户信息，支持筛选、分页、批量操作。

**API 路径**：`GET /api/v1/users`

**触发方式**：

1. 点击菜单“系统管理-用户管理”；
2. 用户操作（新建/编辑/删除）后的自动回退。
   ... (unchanged)
   **边界条件**：

- 单页上限：100条；
- 查询响应 ≤ 3秒；
- 批量操作上限：50条；
- 不可删除当前登录用户及系统超管。

#### 1.1.3 编辑用户

**功能描述**：修改已有系统用户信息及权限。

**API 路径**：`PUT /api/v1/users/:id`

**触发方式**：点击“编辑”按钮。
... (unchanged)

#### 1.1.4 删除用户

**功能描述**：清理无效账号。删除后不可登录，不再显示在常规列表。

**API 路径**：`DELETE /api/v1/users/:id`

**触发方式**：点击周期或批量“删除”按钮。
... (unchanged)

#### 1.1.5 角色管理

**功能描述**：定义系统岗位及其关联的菜单权限与数据范围。

**API 路径**：

- 列表筛选：`GET /api/v1/roles`
- 新增角色：`POST /api/v1/roles`
- 获取详情：`GET /api/v1/roles/:id`
- 更新角色：`PUT /api/v1/roles/:id`
- 删除角色：`DELETE /api/v1/roles/:id`
- 状态切换：`PUT /api/v1/roles/:id/status`
- 获取授权菜单：`GET /api/v1/roles/:id/menus`
- 赋予菜单权限：`POST /api/v1/roles/:id/menus`
- 赋予数据权限：`POST /api/v1/roles/:id/depts`
- 角色克隆：`POST /api/v1/roles/:id/copy`

**核心逻辑**：

1. **RBAC模型**：用户通过关联角色获得权限；
2. **数据脱敏**：角色可配置“仅本人”、“本科室”、“全院”数据查看范围。

#### 1.1.6 菜单权限管理

**功能描述**：维护系统左侧菜单树、页面内操作按钮、以及后端 API 鉴权标识。

**API 路径**：

- 树形列表：`GET /api/v1/menus/list/tree`
- 新增资源：`POST /api/v1/menus`
- 资源详情：`GET /api/v1/menus/:id`
- 修改资源：`PUT /api/v1/menus/:id`
- 删除资源：`DELETE /api/v1/menus/:id`

**资源类型**：

- **目录**：作为菜单容器，无实际路由或 API 匹配；
- **菜单**：对应前端路由，可配置 Lucide 图标；
- **按钮/权限**：对应页面操作或 API 鉴权码（如 `sys:user:edit`）。

#### 1.1.7 系统参数配置

**功能描述**：由超级管理员维护系统全局运行时参数。

**API 路径**：

- 获取配置：`GET /api/v1/sys/config`
- 更新配置：`PUT /api/v1/sys/config/:key`

**可配置项**：

- 系统名称与 LOGO；
- 随访计划自动触发开关；
- 用户登录失败锁定及验证码阈值；
- 初始密码强度要求。

### 1.2 医生管理

#### 1.2.1 新建医生档案

**功能描述**：录入医生基础及执业信息，关联科室与系统账号。

**触发方式**：点击“新增医生”按钮。

**前置条件**：拥有“人员管理-新增”权限，字典（科室、职称、角色）已配置。

**输入**：

- **必填数据**：姓名、手机号（登录名）、所属科室、职称、角色权限
- **可选数据**：工号、简介、擅长领域、头像（<2MB, jpg/png）
- **自动获取**：医生ID、创建时间、创建人

**输出（成功时）**：

1. Toast 提示：“医生档案创建成功”；
2. 跳转至详情或列表页。

**边界条件**：

- 医生数量上限：默认2000人；
- 手机号全系统唯一；
- 图片上传异常处理及格式校验。

#### 1.2.2 编辑医生档案

**功能描述**：维护医生实时执业信息及权限。

**触发方式**：点击“编辑”。

**输入**：

- 可修改项包含必填基础信息、工号、简介、头像等。
- 只读项包括医生ID、创建时间。

**输出（成功时）**：

1. 提示更新成功；
2. 权限及状态变更实时生效。

**边界条件**：

- 审计日志记录所有变更字段。

#### 1.2.3 删除医生档案

**功能描述**：执行离职或错误数据的清理。

**触发方式**：触发“删除”按钮。

**行为**：二次确认确认后删除。

> 确认删除该医生？删除后该账号将无法登录系统，此操作不可恢复。

**边界条件**：

- 默认逻辑删除。
- 账号强制过期时间 ≤ 1分钟。

#### 1.2.4 医生批量导入

**功能描述**：通过 Excel 模板快速录入多名医生。

**触发方式**：点击“批量导入”。

**输入**：

- 上传文件（.xlsx, ≤ 5MB）

**处理逻辑**：

1. 校验文件格式及必填项；
2. 全局唯一性检查（手机号）；
3. 字典匹配性检查（科室、职称、权限）。

**输出**：

- 显示成功/失败条数；
- 提供失败明细 Excel 下载。

**边界条件**：

- 单次上限：5000条；
- 处理响应：5000条 ≤ 60秒。

### 1.3 科室管理

#### 1.3.1 科室列表

**功能描述**：管理科室组织架构及状态。

**API 路径**：`GET /api/v1/depts`

**触发方式**：点击菜单“组织架构-科室管理”。

**展示字段**：科室名称、编码、上级科室、负责人、电话、状态、创建时间。

**边界条件**：

- 默认按创建时间倒序；
- 查询响应 ≤ 3秒。

#### 1.3.2 新增科室

**功能描述**：建立组织层级。

**API 路径**：`POST /api/v1/depts`

**输入**：

- **必填数据**：名称（院内唯一）、编码（唯一）、上级科室（可空）、状态

**边界条件**：

- 最大层级：5级；
- 科室总数上限：500个。

#### 1.3.3 编辑科室

**功能描述**：调整名称、关联关系及详情。

**API 路径**：`PUT /api/v1/depts/:id`

**约束**：不可将上级设置为自身或其子级（循环校验）。

#### 1.3.4 删除科室

**功能描述**：逻辑删除科室。

**API 路径**：`DELETE /api/v1/depts/:id`

**规则要求**：

1. 存在医生或子科室时禁止删除；
2. 保留科室不得删除。

#### 1.3.5 科室状态切换

**API 路径**：`PUT /api/v1/depts/:id/status`

**影响**：禁用后不可分配新医生，但不影响历史归属。

### 1.4 组织架构可视化（树形管理）

#### 1.4.1 层级树形视图展示

**功能描述**：以树状结构动态展示医院、科室、以及医生账户的实时归属关系。

**API 路径**：`GET /api/v1/org-tree`

**触发方式**：点击菜单“系统管理-组织架构（树形）”。

**展示字段**：

- 节点名称（医院/科室/医生）
- 统计数据（下级科室数、医生人数）
- 节点状态（启用/停用）

**交互逻辑**：

1. 默认折叠，支持全局“展开/折叠”及单节点点击操作；
2. 点击医生节点，侧边栏弹出该医生的快速详情及权限摘要；
3. 支持搜索关键字快速定位节点。

#### 1.4.2 拖拽调整维护

**功能描述**：支持通过可视化的拖拽交互调整科室的隶属层级或医生的所属科室。

**触发方式**：在树形视图中选中节点并拖动至目标父节点。

**前置条件**：拥有“组织架构管理”权限。

**约束规则**：

1. **科室迁移**：不可将某一科室拖入其自身的子科室中（防止逻辑死循环）；
2. **医生调科**：医生仅能在合法的科室节点间移动；
3. **并发控制**：拖拽操作时锁定当前分支，防止多人同时修改冲突。

**输出**：操作成功后弹出 Toast 提示“架构更新成功”，并实时刷新树形视图。

#### 1.4.3 批量导入/导出医生

**功能描述**：通过标准模板实现全院范围内医生账号及其科室映射关系的批量初始化与维护。

**输入**：

- **导入**：上传 Excel 文件（.xlsx），包含：姓名、工号、手机号、科室全路径（如：总院/内科/呼吸科）、职称。
- **导出**：根据选中的树级节点，增量下载对应的医生数据明细。

**处理逻辑**：

1. 系统根据“科室全路径”自动进行字典匹配；
2. 若路径不存在，导入过程中支持自动创建未知科室（需二次确认）。

**边界条件**：

- 单次操作上限：5000 条数据；
- 系统响应时间：1000 条/10 秒以内。

#### 1.4.4 权限下放（节点管理员）

**功能描述**：设置“节点管理员（科室管理员）”，实现管理权责的按级下放与数据自治。

**输入**：

- 目标节点（科室）
- 选定用户（即管理员）
- 管理权限集（账号管理、计划维护、数据导出）

**管理范围**：

1. 管理员仅对自己所属节点及其所有后代节点拥有写权限；
2. 不可跨科室查看或修改无关分支。

**输出**：委任成功后，该管理员登录系统将仅能访问其权限范围内的资源。

**边界条件**：

- 系统强制校验：删除节点管理员或调离原科室时，系统自动解除管理标记；
- 审计记录：所有节点委任与撤职必须录入系统审计日志。

## 2. 患者管理

### 2.1 患者分组

#### 2.1.1 创建分组

**功能描述**：建立静态（手动选择）或动态（条件筛选）患者群。

**分组类型**：

- **静态分组**：手动维护成员。
- **动态分组**：根据病种、手术、年龄、性别等条件自动聚合。

**输出**：

- 动态分组自动刷新计算结果。

**边界条件**：

- 分组上限：5000个。
- 筛选条件组合 ≤ 10个。

#### 2.1.2 管理分组（编辑/删除/查看）

**删除限制**：被随访计划引用的分组禁止删除。

**查看列表**：

- 展示脱敏后的患者基本信息（如：张\*三、138\*\*\*\*1234）。

### 2.2 患者档案

#### 2.2.1 新建患者档案

**功能描述**：建立患者的核心诊疗档案。

**输入**：

- **必填数据**：姓名、身份证号（唯一）、性别（自动识别）、生日（自动识别）、手机号、主诊断。
- **可选数据**：住院号、手术信息、主管医生、自定义扩展字段。

**输出**：

- 若开启自动随访，根据手术时间自动生成随访任务。

**边界条件**：

- 年龄自动精准计算。
- 单个档案扩展字段 ≤ 50个。

#### 2.2.2 档案维护与查看

**编辑限制**：身份证号、性别、出生日期建档后不可修改。

**详情展示**：

- 分 Tab 展示：基本信息、诊疗信息、扩展信息、随访记录、操作日志。

#### 2.2.3 扩展字段配置

**功能描述**：管理员自定义患者档案的扩展字段，控制字段在医生端和患者端的可见性与可编辑性。

**可配置项**：

- 字段名、类型（文本/数字/日期/单选等）、是否必填。
- 医生端/患者端及其可见性、编辑性。

#### 2.2.4 患者档案导入

**功能描述**：批量初始化或同步患者数据。

**规则**：

- 单次量 ≤ 5000条。
- 身份证号重复冲突处理：跳过/覆盖。
- 并发控制：同一用户不可并发多个导入任务。
