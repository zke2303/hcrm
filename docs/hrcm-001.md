# 《医院全科随访系统》产品说明书

---

## 一、系统概述

医院全科随访系统是一款覆盖医院管理端、医生工作端和患者服务端的全流程随访管理平台，旨在提升随访效率、加强医患互动、优化慢性病与术后患者的长期健康管理。

---

## 二、医院管理端（Web）

### 1. 系统管理

- 医院/科室/医生层级管理
  - 实现描述：以树形结构可视化维护医院组织架构。支持拖拽调整科室归属，批量导入/导出医生账户。每个节点可设置管理员，实现权限下放。
- 角色与权限配置
  - 实现描述：提供基于RBAC（角色权限访问控制）模型的配置界面。可创建如“随访专员”、“数据查看员”等角色，通过勾选方式精细分配菜单、按钮及数据访问（如仅本科室数据）权限。
- 功能模块开关与个性化配置
  - 实现描述：后台提供功能模块的启用/禁用开关，并可配置系统名称、LOGO、随访计划触发规则（如术后第3天开始）等全局参数。
- 操作日志审计
  - 实现描述：系统自动记录关键操作（如删除患者、修改随访模板、导出数据）的人员、时间、IP及内容详情，支持按条件查询和导出日志报表。

### 2. 患者主数据管理

- 全院患者档案统一视图
  - 实现描述：提供集成的患者信息仪表板，综合展示从HIS同步的基础信息、历次随访记录、用药计划等。支持一键穿透查看详情。
- 患者信息批量导入/导出（对接HIS）
  - 实现描述：提供标准Excel模板供离线批量维护。核心是与医院HIS系统通过中间库或API接口实现定时/实时同步，采用患者ID或病案号作为唯一标识进行匹配与增量更新。
- 患者分组管理
  - 实现描述：支持通过“病种+手术+时间”等多条件组合，动态或静态创建患者分组（如“2023年Q4膝关节置换术后患者”），用于批量任务分配或消息推送。
- 患者档案字段自定义
  - 实现描述：管理员可后台添加扩展字段（如“过敏史详细”、“家庭住址”），并控制字段在医生端或患者端的可见与可编辑性。

### 3. 随访计划模板库

- 内置常见病种随访模板
  - 实现描述：系统预置经过医学专家评审的标准随访模板库，包含标准评估量表（如PHQ-9抑郁量表）和问题集，医院可直接引用或微调后使用。
- 自定义问卷/量表设计器
  - 实现描述：提供可视化的拖拽式表单设计器，支持添加单选题、多选题、评分题、文本题等，可设置跳转逻辑和必填项。
- 随访流程与规则引擎配置
  - 实现描述：可图形化配置随访流程，例如：“出院后第1、3、7天发送问卷，若第7天评分>10分，则自动创建医生人工随访任务”。
- 模板发布与科室共享管理
  - 实现描述：模板需经过“保存-测试-发布”流程方可正式使用。可设置模板为全院公开或指定科室专用。

### 4. 任务调度与监控

- 自动随访任务生成与分配
  - 实现描述：系统后台服务根据随访计划规则，每日自动生成任务。支持按规则（如按患者归属或医生负载）自动分配，或批量手动分配至医生或随访团队。
- 全院随访任务看板
  - 实现描述：以卡片或列表形式集中展示所有待办、逾期、已完成的任务，支持按状态、科室、医生等多维度筛选和快速处理。
- 随访完成率、响应率统计
  - 实现描述：自动计算并实时更新各维度统计指标，通过进度条、百分比数字等形式直观展示，数据可下钻分析。
- 异常任务预警与重新分配
  - 实现描述：对逾期未处理或患者反馈异常（如上报剧烈疼痛）的任务，系统通过站内信、短信等方式预警管理员，并支持一键将任务重新分配给其他医生。

### 5. 数据分析与报表

- 随访数据多维度统计
  - 实现描述：提供灵活的报表生成器，可跨科室、病种、时间周期对随访结果数据进行交叉统计，生成图表（柱状图、折线图、饼图）。
- 患者满意度分析
  - 实现描述：自动汇总患者端提交的满意度评分与文本评价，进行趋势分析和关键词提取，生成满意度报告。
- 关键指标趋势报表
  - 实现描述：预定义关键业务指标（如慢病患者血压/血糖控制率、术后并发症发生率），支持生成随时间变化的趋势图表，并可导出为PDF或PPT。
- 数据驾驶舱与可视化大屏
  - 实现描述：为院领导提供一站式数据总览视图，集成核心KPI，支持全屏播放，用于会议展示或监控中心。

### 6. 消息推送管理

- 全院通知公告发布
  - 实现描述：富文本编辑器编写通知，可选择发布范围（全院、指定科室），发布后医生端和患者端会有小红点提醒。
- 短信/消息模板管理
  - 实现描述：管理所有对外发送的短信、小程序消息模板内容，支持变量（如{患者姓名}、{用药时间}）替换，并需符合运营商审核规范。
- 推送记录与到达率统计
  - 实现描述：记录每一条推送消息的发送状态、到达状态、阅读状态，形成明细日志，并统计各渠道的到达率与打开率。

## 三、医生工作端（Web + App）

### 1. 工作台

- 今日待办随访任务提醒
  - 实现描述：登录后首页顶部显著位置显示今日需处理的自动随访任务和患者主动咨询消息数量，点击直接进入处理界面。
- 紧急/异常患者预警面板
  - 实现描述：系统自动筛选出上报严重症状或指标超阈值（如血压>180/110mmHg）的患者，以红色警示标签集中显示，便于医生优先处理。
- 快捷新建随访
  - 实现描述：提供快速入口，允许医生跳出固定计划，随时为指定患者发起一次性的随访或沟通。

### 2. 患者管理

- 我的患者列表与筛选
  - 实现描述：列表展示所有归属或分配到本人的患者，支持按姓名、病种、标签、最近随访时间等多种条件快速筛选和搜索。
- 患者详情查看
  - 实现描述：以时间轴或标签页形式，集成展现患者全貌：基本信息、历史诊断（从HIS同步）、全部随访记录、用药计划、上传的图片等。
- 手动添加/分配患者
  - 实现描述：通过输入患者ID或扫描就诊卡条码，将未在系统内的患者手动添加到自己的患者库中，或从全院库中认领患者。
- 患者标签与分组
  - 实现描述：医生可为患者打上自定义标签（如“依从性差”、“需重点关注”），并基于标签创建动态分组，便于分类管理。

### 3. 随访执行

|- 数字人辅助随访 - 实现描述：医生可查看数字人与患者交互的完整记录，包括对话内容、患者情绪状态分析和关键健康指标提取。医生可对数字人生成的随访摘要进行审核、补充或修正。
|- 语音/文字快捷回复模板 - 实现描述：医生可维护个人常用语模板库（如“请按时服药，定期复查”），在填写建议或回复消息时一键插入，支持语音输入转文字。数字人可学习医生的回复风格，提供更个性化的患者交互。
|- 随访记录自动保存与归档 - 实现描述：数字人与患者的交互记录自动保存，医生审核后生成不可更改的正式随访记录，归档至患者档案，并生成时间戳和电子签名。
|- 支持图片、语音上传 - 实现描述：在随访记录中，医生可拍摄或从相册上传患者伤口恢复照片等，也可录制语音备注，作为多媒体附件保存。数字人可引导患者上传相关图片或视频，辅助医生远程评估。

### 4. 用药与健康教育

- 为患者创建用药计划
  - 实现描述：通过表单为患者设定用药方案，包括药品名、剂量、频次（每日几次）、用法（口服/外用）、起止日期，系统将据此生成患者端的用药提醒。
- 常用医嘱模板库
  - 实现描述：医生可创建和调用个性化的医嘱模板（包含常用药品组合和指导建议），快速生成用药计划，提升效率。
- 健康知识库推送
  - 实现描述：医生可以从医院审核过的知识库中，选择相关的健康教育文章或视频，一键分享给指定患者或患者群组。
- 用药记录查看
  - 实现描述：可查看患者端的用药打卡记录，了解患者的依从性情况，对未按时打卡的患者可手动提醒。

### 5. 沟通与互动

- 患者消息列表
  - 实现描述：类似聊天软件界面，按患者聚合消息。医生可在此与患者进行非计划性的文字、图片沟通，所有记录留存。
- 重要事项一键电话拨打
  - 实现描述：在患者详情页点击电话图标，直接调用手机拨号功能拨打患者预留电话，系统可选记录本次通话摘要。
- 随访日程日历视图
  - 实现描述：以日历形式直观展示未来待办的随访任务和已安排的复诊计划，支持月、周、日视图切换。

### 6. 个人数据统计

- 个人随访工作量统计
  - 实现描述：展示医生个人的月度/年度随访任务量、完成率、平均响应时间等数据，支持与科室平均水平对比。
- 患者管理效果指标
  - 实现描述：提供医生所管理患者群体的关键健康指标统计，如糖尿病患者血糖达标率变化，辅助评估管理成效。
- 患者满意度反馈查看
  - 实现描述：集中查看患者对自己的匿名评分和文字评价，帮助改进服务质量。

## 四、患者端（微信小程序）

### 1. 个人中心

- 注册登录与实名认证
  - 实现描述：支持手机号+验证码登录。首次登录需通过人脸识别或输入姓名、身份证号与医院登记信息匹配，完成实名认证和档案绑定。
- 个人信息维护
  - 实现描述：允许患者补充或更新非核心个人信息，如联系电话、紧急联系人、家庭地址等。
- 绑定/切换主诊医生
  - 实现描述：患者可查看并申请绑定有随访关系的医生，经医生端确认后建立联系。支持在多位医生间切换对话。

### 2. 我的档案

- 查看个人基本健康信息
  - 实现描述：安全地展示从医院同步的姓名、性别、年龄、血型、主要诊断等基本信息。
- 历史就诊记录摘要
  - 实现描述：列表展示历次住院/门诊的摘要，包括时间、科室、主要诊断，保护详细病历隐私。
- 历次随访记录与医生建议
  - 实现描述：以时间倒序排列所有完成的随访记录，患者可查看自己填写的答案和医生的详细回复与建议。
- 检查报告上传与查看
  - 实现描述：患者可拍摄或上传在其他医院的检查报告单，系统尝试OCR识别关键信息，供医生参考。

### 3. 随访互动

- 交互式数字人随访
  - 实现描述：患者通过与AI数字人进行自然语言对话完成随访，数字人以拟人化形象出现，通过语音和文字与患者互动，引导患者回答随访问题，支持语音识别和自然语言理解，提供更人性化的随访体验。
- 智能症状评估与上报
  - 实现描述：数字人可根据患者描述的症状进行智能分析，引导患者提供更详细的症状信息，并自动将关键信息结构化，生成待医生处理的消息。
- 与医生一对一消息沟通
  - 实现描述：在聊天界面中，患者可随时向绑定的医生发送文字、图片、语音消息，进行轻量级咨询。数字人可作为中介，帮助患者整理问题并提供初步建议。
- 满意度评价
  - 实现描述：在每次随访任务或咨询结束后，系统邀请患者对本次服务（包括数字人交互体验）进行五星评分和可选文字评价。

### 4. 用药管理

- 查看医生制定的用药计划
  - 实现描述：清晰列表展示当前所有在用药品的名称、用法用量、服用周期，并显著标识“待服用”、“已跳过”等状态。
- 每日用药提醒推送
  - 实现描述：系统根据用药计划，在每日设定的服药时间（可自定义）通过小程序消息或微信小程序推送发送提醒，点击可直达打卡页面。
- 用药打卡记录
  - 实现描述：患者点击“已服用”按钮完成打卡，系统记录打卡时间。也提供“跳过”并选择原因（如“忘记”、“不适”）。
- 药品余量提醒
  - 实现描述：患者可手动设置药品预计用完日期，系统将在到期前适当天数发送提醒，告知可能需要复诊开药。

### 5. 健康计划与提醒

- 复诊提醒设置与通知
  - 实现描述：患者或医生可创建复诊计划（时间、科室），系统在复诊日前1天、当天早上推送提醒。
- 健康任务打卡
  - 实现描述：医生可为患者布置每日健康任务（如“测量血压并记录”），患者在此处记录测量值，形成历史曲线图。
- 接收健康科普文章/视频
  - 实现描述：患者可订阅感兴趣的病种专栏，定期接收系统推送的由医院生产的权威健康资讯。
- 自定义健康笔记
  - 实现描述：提供私人笔记功能，患者可记录每日身体感受、饮食情况等，仅供个人查看。

### 6. 紧急联系

- 查看科室/医生联系电话
  - 实现描述：在“我的医生”页面或专用“紧急联系”页面，展示科室工作电话和医生（在隐私设置允许下）的联系方式。
- 紧急情况一键求助
  - 实现描述：设置醒目的“一键求助”按钮，点击后可将预设的求助信息（含患者位置信息，需授权）同时发送给绑定的医生和紧急联系人。
- 附近医院/急救指南
  - 实现描述：集成地图服务，显示附近的医院和急救中心位置与路线，并提供基础的急救知识图文指南。

## 五、通用功能

### 1. 消息中心

- 系统消息、用药提醒、随访通知
  - 实现描述：各端统一的消息聚合中心，分类显示各类消息。支持标记已读、批量删除。
- 多渠道推送
  - 实现描述：根据消息优先级和类型，智能选择推送渠道：高频、及时的提醒用微信小程序推送或小程序订阅消息；重要通知辅以短信。
- 消息阅读状态跟踪
  - 实现描述：对于重要通知，系统能跟踪到每位用户的阅读状态（已读/未读），便于管理者跟进。

### 2. 数据同步与对接

- 与医院HIS/LIS/PACS系统对接
  - 实现描述：通过医院信息集成平台或直接数据库接口，定时（如每夜）或实时同步患者、诊断、检验检查关键数据。采用患者主索引进行匹配。
- 支持标准接口
  - 实现描述：对外提供符合HL7 FHIR标准的API接口，方便与区域健康平台或其他第三方系统进行数据交换。
- 数据加密与隐私保护
  - 实现描述：数据传输全程使用TLS 1.2+加密。敏感数据（如联系方式）在存储时进行脱敏或加密处理，严格遵循《个人信息保护法》和医疗数据安全规范。

### 3. 多端协同

- 数据实时同步
  - 实现描述：基于WebSocket或长轮询技术，确保医生在Web端提交的随访记录能实时出现在患者微信小程序信小程序端，反之亦然。
- 离线数据暂存与恢复
  - 实现描述：移动端（医生App、患者微信小程序）在无网络时，可将填写的表单、消息等暂存本地，待网络恢复后自动同步至服务器。

## 六、非功能性需求

### 1. 性能与安全

- 响应时间：前端页面加载<3秒，列表查询<2秒，复杂统计报表生成<10秒。
- 系统可用性：核心随访业务模块可用性>99.5%，计划内维护需提前公告。
- 数据传输加密：全站启用HTTPS，对敏感API请求进行签名验证，防止重放攻击。
- 患者数据脱敏与隐私合规：建立数据分级分类制度，确保匿名化处理符合等保2.0三级要求及医疗行业隐私标准。

### 2. 扩展性与集成

- 模块化设计：采用微服务或清晰模块化架构，新功能（如康复训练模块）可作为独立插件接入。
- 提供开放API：提供完备的API文档和沙箱环境，供第三方科研系统或可穿戴设备接入数据。
- 支持多种部署方式：支持公有云SaaS化部署和医院内网私有化部署，满足不同安全策略需求。

### 3. 用户体验

- 界面简洁易用：医生端界面设计符合临床工作流程，减少点击步骤；患者端界面字体清晰、操作简单，适应中老年用户。
